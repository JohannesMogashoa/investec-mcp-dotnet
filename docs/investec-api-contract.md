# Investec Private Banking API contract

Issue #3 research, reviewed 2026-11-24. This covers South African Private Banking Direct API access for individuals and private businesses. The primary local reference is [Private Bank OpenAPI 1.0.1](sa-pb-account-information.yaml). Its schemas and examples are documentation, not observed API behavior; no sandbox or production credentials were available.

## Token and credentials

Production token endpoint is `POST https://openapi.investec.com/identity/v2/oauth2/token`. Send HTTP Basic authentication with the client ID and secret, the `x-api-key` header, and an `application/x-www-form-urlencoded` body with `grant_type=client_credentials`. The documented success response is a top-level object with `access_token` (string), `token_type` (string, example `Bearer`), `expires_in` (integer seconds), and `scope` (string). The example lifetime is about 30 minutes. Use the returned lifetime and obtain a new token with the same grant when needed. [Investec OAuth reference](https://developer.investec.com/api-reference/SA%20Open%20API%20-%20Authorization) · [Investec token request and response example](https://www.postman.com/investec-open-api/programmable-banking/documentation/hl5nm0u/investec-programmable-card-api?entity=request-26868804-134c35c6-8af1-481e-93f1-d708a22f275c)

In Investec Online, the main account holder can create a key under **Manage → Bank integrations → Direct API → Connection** and select the accounts and permissions separately. The OpenAPI operations declare `accounts` for account discovery, `balances` for balance reads, and `transactions` for transaction reads, for both production and sandbox security requirements. The published token example returns `accounts` only; it does not demonstrate that this grant covers all three endpoints. Request only those three declared read scopes and restrict the key to approved accounts. The precise labels shown in the personal key creation UI and live enforcement still require confirmation. [Private Bank OpenAPI operations](sa-pb-account-information.yaml) · [Investec individual access setup](https://developer.investec.com/individuals)

## Read endpoints and response fields

Production base URL is `https://openapi.investec.com/za/pb/v1`. Send `Authorization: Bearer <token>` and `Accept: application/json` on all three GETs. No request body is needed. Published success envelopes include `data`, `links.self` (string), and `meta.totalPages` (integer). [Investec Private Bank API](https://developer.investec.com/api-reference/SA%20PB%20Account%20Information) · [Investec Private Bank Postman collection](https://www.postman.com/investec-open-api/programmable-banking/collection/gly7cw5/investec-programmable-banking-pb)

| Request | Observed success payload inside `data` |
| --- | --- |
| `GET /accounts` | `accounts` array. Items have string `accountId`, `accountNumber`, `referenceName`, `productName`, and `profileId`, boolean `kycCompliant`, and string `accountName` when present. The example omits `accountName` on one item and omits currency from account discovery. [Accounts example](https://www.postman.com/investec-open-api/programmable-banking/request/wnb2z4r/get-accounts) |
| `GET /accounts/{accountId}/balance` | Object with string `accountId` and `currency`, and numeric `currentBalance` and `availableBalance`. Read monetary JSON numbers as decimals. [Balance example](https://www.postman.com/investec-open-api/programmable-banking/request/9iqrn4d/account-balance) |
| `GET /accounts/{accountId}/transactions?fromDate=YYYY-MM-DD&toDate=YYYY-MM-DD` | `transactions` array. Items include strings `accountId`, `type`, `transactionType`, `status`, `description`, and `cardNumber`; integer `postedOrder`; date strings `postingDate`, `valueDate`, `actionDate`, and `transactionDate`; and numeric `amount` and `runningBalance`. The example includes a positive amount on a debit. Preserve amount and direction separately in upstream DTOs. [Private Banking transaction example](https://investec.gitbook.io/programmable-banking-community-wiki/get-started/api-quick-start-guide/how-to-get-your-transaction-history) |

Use the exact `accountId` from account discovery as an opaque string. The documented values can exceed integer precision and differ from `accountNumber` and `profileId`. The OpenAPI path parameters for balance and transactions declare a 30-character maximum, while the transaction item schema allows 40 characters; do not infer a universal account ID limit from this inconsistent document. Validate membership in the local authorized set before escaping it as a single path segment. Avoid exposing full account numbers, card references, or profile IDs in MCP output. [Private Bank OpenAPI schemas](sa-pb-account-information.yaml) · [Accounts example](https://www.postman.com/investec-open-api/programmable-banking/request/wnb2z4r/get-accounts)

## Transaction dates, pagination, and errors

The OpenAPI transaction operation filters by `postingDate` and accepts `fromDate` and `toDate` query strings. If omitted, it documents defaults of today minus 180 days and today, respectively. This connector requires both dates and limits the window to 90 calendar days by default, so it never relies on those broader upstream defaults. The OpenAPI file does not specify a maximum lookback or span, boundary inclusivity, timezone, or future-date handling; these still need sandbox and production verification. Posting date is when the transaction affects the account balance, while transaction date is when the underlying activity occurred. [Private Bank OpenAPI transaction operation](sa-pb-account-information.yaml) · [Investec transaction quickstart](https://investec.gitbook.io/programmable-banking-community-wiki/get-started/api-quick-start-guide/how-to-get-your-transaction-history)

The OpenAPI response schema includes `meta.totalPages`, but the transaction operation declares no page, size, offset, or continuation query parameter. It also declares optional `transactionType` and `includePending`; the latter is described as including pending transactions when `true`. A separate pending-transactions endpoint exists. The public quickstart mentions pagination without defining the request contract. Automatic paging remains deferred until Investec confirms its request parameters, numbering, size limits, and ordering. A response with more than one total page, or contradictory `currentPage` metadata if that extension appears, is rejected before any balance lookup or MCP output. Route any future page request through the fixed gateway. [Private Bank OpenAPI transaction operation](sa-pb-account-information.yaml) · [Transaction quickstart](https://investec.gitbook.io/programmable-banking-community-wiki/get-started/api-quick-start-guide/how-to-get-your-transaction-history)

Investec's individual API FAQ says `postedOrder` may initially be `0` and change after settlement. This connector preserves the field and does not infer that `0` represents a final posted sequence. The same FAQ confirms `transactionDate` is the activity date and `postingDate` is when the amount is deducted from the balance. [Investec individual API FAQ](https://developer.investec.com/individuals)

Exact OAuth and Private Banking error response schemas, status distinctions for missing versus unauthorized accounts, and throttling headers remain unverified. For #09 and #15, use HTTP status as the primary classification input, tolerate non-JSON error bodies, and keep raw upstream errors out of MCP responses. Add vendor-specific error parsing only after capturing a de-identified contract. [Investec OAuth reference](https://developer.investec.com/api-reference/SA%20Open%20API%20-%20Authorization) · [Investec Private Bank reference](https://developer.investec.com/api-reference/SA%20PB%20Account%20Information)

## Sandbox and open issues

Investec offers a mock-data sandbox at `https://openapisandbox.investec.com`. Its portal points users to the sandbox credential guide. Sandbox calls can help verify HTTP behavior. Production key-level restrictions require separate confirmation with a personal connection restricted to approved accounts and read permissions.
